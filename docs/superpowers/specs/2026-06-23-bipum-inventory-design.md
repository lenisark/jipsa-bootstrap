# 비품관리 시스템 설계 (jipsa supply/inventory)

> **상태:** 설계 검토 중 → 승인 후 writing-plans 로 구현 계획 작성.
> **한 줄:** 비품신청 **슬랙 리스트**(출고)와 **비품 주문 기록 엑셀**(입고)의 *자유텍스트 품목명*을 **LLM으로 정규화·매칭(캐시 사전)**해 품목별 재고를 구글드라이브 .xlsx로 자동 관리하고, 저재고·신규품목·차감을 슬랙으로 알린다.

## 1. 목표와 비목표

**목표**
- **출고**: 슬랙 리스트 신청이 `수령완료`되면 해당 품목 재고를 수량만큼 차감.
- **입고**: `비품 주문 기록` 엑셀의 사내비품 발주를 재고에 가산(+ 수동 `입고` 명령).
- **자유텍스트 품목 매칭**: LLM이 품목명을 canonical 품목으로 정규화/매칭, 애매하면 슬랙 확인, 결정은 **사전 캐시**(이후 LLM 없이 결정적).
- 품목별 현재 재고를 구글드라이브 .xlsx로 관리(팀 열람·편집), 저재고/신규품목/차감 슬랙 알림, 지급/입고 이력 누적.

**불변식 — 신뢰성**
- **재고 수량 계산은 100% 결정적**(정수 가감). LLM은 *이름→canonical 매칭*에만 쓰고, 그 결과는 사전에 캐시되어 재실행해도 동일.

**비목표**
- 리스트에 상태 되써넣기(jipsa는 리스트 **읽기 전용**; `lists:write`는 추후).
- 발주/구매·결재 자동화. 비품신청 접수 자체(기존 워크플로 유지).

## 4. 데이터 모델

**`비품재고_현황.xlsx` 시트 `재고`** (canonical 품목 기준)
| 품목(canonical) | 카테고리 | 현재수량 | 최소수량 | 단위 | 비고 |
|---|---|---|---|---|---|

**시트 `별칭`** (LLM 매칭 캐시 — 결정적 재사용)
| 원문품목 | canonical품목 | 출처(list/order) | 확신도 | 결정방식(auto/confirm) | 결정시각 |
|---|---|---|---|---|---|

**`비품_입출고이력.xlsx`**
| 일시 | 유형(입고/출고) | canonical품목 | 원문품목 | 수량 | 처리후잔여 | 신청자/발주처 | 출처키(record_id/주문행) |

## 5. 아키텍처

```
[슬랙 리스트]──폴링(lists:read)─┐
[비품 주문 기록 .xlsx]──읽기────┤→ [supply.py 이벤트 수집] (출처키로 멱등)
                                │        │ 각 이벤트: (원문품목, 수량, 유형, 출처키)
                                ▼        ▼
                     [품목 정규화 엔진] ──사전(별칭)에 있으면 즉시─▶ canonical
                          │ 없으면 Claude 호출(기존 canonical 목록+카테고리 어휘 제공)
                          │   high → auto 매칭 + 사전 기록
                          │   low/애매 → 슬랙 확인 카드[예/새 품목] + 이벤트 보류(pending)
                          ▼
              [재고 계산: 결정적 정수 가감] ─▶ 비품재고_현황.xlsx (원자적 쓰기)
                          └─▶ 비품_입출고이력.xlsx + 슬랙 알림(차감/입고/저재고/신규)
```

- **`supply.py`** (daemon 형제): 폴링 루프 · 리스트/엑셀 파싱 · 정규화 엔진 호출 · 재고 가감 · xlsx I/O · 알림 · pending 큐.
- **정규화 엔진**: `resolve(원문, 출처)→canonical`. ① 정규화(공백/대소문자/꼬리수량 분리) ② 별칭 사전 조회 ③ 미스 시 Claude(`_run_claude` 재사용, 새 세션, JSON 출력) → {match|NEW, canonical, category, confidence}. ④ high면 자동+사전기록, 아니면 슬랙 확인.
- **확인 플로우**: 기존 `approval.py`/`handle_block_action` 인프라 재사용 — action_id `item_confirm`/`item_new`, value=pending_id. 결정 시 별칭 기록 후 보류 이벤트 처리.
- **상태/멱등**: `supply_state.json`(로컬) — 처리한 출처키(list record_id / 주문 행 해시), baseline_done, pending 큐.

## 6. 동작 상세

**출고 폴링(poll_min 분):** 리스트 읽기 → `상태==수령완료 && 출처키∉처리됨` → 정규화 엔진으로 canonical 확정(또는 pending) → `재고 -= 수량` → 이력 append → 처리됨 기록 → 알림. 저재고면 경고.

**입고(P2):** `비품 주문 기록_*.xlsx`의 신규 행(출처키=파일+행해시) 중 `용도==사내비품` → 정규화 → `재고 += 수량` → 이력. (공용/재판매는 제외, 설정으로 토글.)

**입고 수동:** `입고 {품목} {수량}` (담당자) → 정규화 → 가산.

**baseline(최초 1회):** 기존 `수령완료` record_id와 기존 주문 행을 **차감/가산 없이** 처리됨으로 등록(과거 이력은 실물에 이미 반영). 이후 신규만 반영. 시작 시점 재고는 실사 입력 권장(없으면 0에서 신규품목으로 축적).

**정규화 결정:** 같은 원문은 한 번만 LLM → 별칭 캐시 → 이후 항상 동일. 사람이 별칭 시트를 직접 고쳐 교정 가능.

## 7. 슬랙 명령 (notify_channel = 부서 채널)
- `재고` / `재고 {품목}` — 조회(누구나) · `입고 {품목} {수량}` — 가산(담당자=`USER_SLACK_ID`+`managers[]`) · `비품현황` — 저재고 요약 · `품목통합 {A} {B}` — 별칭 수동 병합(담당자)

## 8. 엣지 / 안전
| 상황 | 처리 |
|---|---|
| 같은 출처키 재처리 | 처리됨 집합으로 1회만(멱등) |
| LLM 매칭 비결정성 | 사전 캐시로 1회만 판단, 이후 결정적. 숫자 계산은 LLM 무관 |
| LLM 사용불가/실패 | "신규/확인필요"로 처리(추측 금지) — pending 큐에 보관, 확인 후 반영 |
| xlsx 엑셀로 열림 | `~$` 감지→지연·재시도, 실패 시 경고. 이벤트는 처리됨 미기록→다음 주기 재시도 |
| 동시 쓰기 | 임시파일+`os.replace` 원자적 |
| 수령완료 후 반려/되돌림 | 이미 차감됨, 자동환원 안 함 → `입고`로 보정(알림 안내) |
| 음수 재고 | 막지 않음(실물 출고 사실)+경고 |
| 수량 0/빈값 | 스킵+경고 |
| 신규품목 | 재고시트 행 추가+알림(카테고리는 LLM 제안) |
| pending 미확인 누적 | `비품현황`/주기 알림으로 미확인 N건 리마인드 |

## 10. 테스트
- **단위(`tests/test_supply.py`)**: 출고 차감/비수령완료 무차감/멱등/baseline/신규품목/저재고/입고 가산/수량0 스킵 · 정규화(별칭 적중→LLM 미호출, 미스→pending) · 리스트/주문 파싱(컬럼→값). LLM은 가짜 resolver 주입(`set_item_resolver`)으로 결정적 테스트.
- **스모크**: 실제 리스트/주문 엑셀 dry-run(차감 없이 매칭·계산 결과만 출력).
- 슬랙/폴링/확인버튼은 라이브 검증.

## 11. 단계 (phase)
- **P1 (핵심)**: 출고(리스트 수령완료)→정규화 엔진(별칭 캐시+슬랙 확인)→비품재고_현황.xlsx 차감+이력+알림+baseline+dry-run.
- **P2**: 입고 — 비품 주문 기록 엑셀 자동 흡수(사내비품) + `입고`/`재고`/`비품현황`/`품목통합` 명령.
- **P3**: 일/주 재고·소진 리포트(알리미 2.0 연동)→폴더에 아카이브 + 슬랙 게시.

## 12. 전제 / 확인 필요
1. ✅ `lists:read`(+`lists:write`) · ✅ `openpyxl` 설치 · ✅ 저장 폴더 확인.
2. **초기 재고 실사값** 있으면 `비품재고_현황.xlsx [재고]`에 미리 채움(정확). 없으면 0 시작.
3. `notify_channel`(부서 채널) 확정 · `managers`(입고 담당자, 기본 본인).
4. 입고 자동흡수 대상 용도: 기본 `사내비품`만(공용/재판매 제외) — 맞는지.
