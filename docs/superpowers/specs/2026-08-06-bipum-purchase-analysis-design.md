# 비품 구매기록·월간분석 전환 설계 (jipsa supply → purchase analytics)

> **상태:** 설계 검토 중 → 승인 후 writing-plans 로 구현 계획 작성.
> **한 줄:** 유지가 어려운 **실시간 재고 추적**을 중단하고, 슬랙에 붙여넣는 **구매표를 '구매 기록'으로 적재**(월별 주문기록 엑셀 append)한 뒤, 매달 그 기록을 **누적 분석 파일**에 반영해 부서·용도·카테고리별 지출을 분석한다. 붙여넣기 UI·파싱·LLM 정규화·별칭 캐시는 재활용한다.
> **선행 결정:** 기존 입고등록/재고 자동화는 *제거하지 않고 중단*(폴링·차감 OFF, 코드·데이터 보존). 재고관리는 후순위.

## 1. 배경과 동기

현재 비품 시스템(P1/P2)은 슬랙 비품신청 리스트의 `수령완료`를 폴링해 재고를 차감하고, 붙여넣은 구매표로 재고를 가산하는 **실시간 재고 추적기**다. 정합성을 유지하려면 입고·출고를 빠짐없이 잡고 별칭 캐시를 계속 손봐야 해서 실제 운영이 어렵다.

실측 결과 **구매 분석 파일이 5월(v1.2)에서 멈춰 있고**, 정작 사용자가 더 가치 있게 여기는 것은 "매달 어떻게 구매하고 있는가"의 **지출 분석**이다. 다행히 슬랙에 붙여넣는 구매표에는 분석에 필요한 **금액·부서가 이미 들어있고**(현재 파서가 버림), 용도·카테고리는 기존 `분류_가이드` 룰북으로 LLM이 거의 결정적으로 분류할 수 있다. 따라서 무게추를 **재고 → 구매 분석**으로 옮긴다.

## 2. 목표와 비목표

**목표**
- **적재**: 슬랙 `#인총-기록저장소`에 붙여넣는 구매표 → 파싱 → 용도·카테고리 분류 → **`비품 주문 기록_YYYYMM.xlsx` 입력시트에 발주 건별 append**("구입리스트 업데이트").
- **분석**: 매달(스케줄) 그 달 월별기록을 **누적 `YYMMDD-HGA-비품주문분석-vN.N.xlsx`** 에 반영(통합원본 append + 피벗/대시보드 갱신 + 버전업), 진행 전 담당자 **확인 게이트**, LibreOffice 재계산으로 합계 정합 검증.
- **백로그 복구**: 5월 이후 밀린 **6~8월** 구매를 슬랙 히스토리(`#인총-기록저장소`)의 붙여넣기 메시지에서 복구해 월별기록·분석에 반영.
- **재활용**: `parse_purchase_table`·`parse_purchase_table_llm`·`resolve_batch_llm`·별칭/분류 캐시·슬랙 붙여넣기 인식 로직.

**불변식 — 신뢰성**
- 금액·수량 등 **수치는 붙여넣기 원본 그대로**(가공/추정 금지). LLM은 *품목명 → (용도·카테고리)* 및 *부서명 정규화*에만 쓰이고, 그 결과는 **분류 캐시**에 저장되어 재실행 시 결정적.
- 분석 파일 병합은 **append-only + 버전 보존**(이전 vN.N 파일 삭제 금지). 병합 후 5개 집계 시트 합계 = 전체 총계 검증 통과해야 확정.

**비목표**
- 실시간 재고 수량 추적(차감/현황) — *중단*이지 재설계 아님. 후순위.
- 발주/결재 자동화, 그룹웨어 직접 연동(기존과 동일하게 없음).
- Google Drive **커넥터(MCP)** 사용 — 로컬 마운트 파일 접근으로 대체(§6).

## 5. 컴포넌트 설계

### 5.1 붙여넣기 → 파싱 (확장)
- `parse_purchase_table`/`_llm` 반환에 **`금액`** 필드 추가(`{품명, 수량, 금액, 부서}`). 규칙 파서는 "품명 뒤 첫 정수=수량, 쉼표 포함 큰 수=금액" 규칙을 이미 알고 있으므로 금액 토큰만 살리면 됨.
- 수량 규칙은 §3.4 기존 정책 유지(품명 규격 보존, 팩 낱개 전개는 **분석엔 불필요** → `parse_pack` 곱셈은 적용하지 않음. 분석은 발주 "건/수량/금액" 기준).

### 5.2 분류 엔진 (신규, 캐시 결정적)
- 입력: 품목명 목록 → 출력: `{품목: {용도, 카테고리}}`. 프롬프트 근거 = `분류_가이드` 시트 텍스트(카테고리 6·용도 3 + 키워드) 주입.
- **부서 정규화**: 붙여넣기 부서 문자열 → `마스터` 부서 어휘 중 최근접(예 "영업1본부"→"영업본부"). 미매칭은 **신규 부서 후보**로 슬랙 고지(월간분석 병합 시 파생 시트에 행 추가 필요).
- **분류 캐시**: `~/.claude/scripts/slack-jipsa/supply_classify.json`(품목→용도·카테고리, 부서 별칭). 기존 재고용 별칭 캐시(비품재고_현황 [별칭])와 **분리** — 재고 시스템 중단과 무관하게 독립 동작. 사람이 JSON 직접 교정 가능.

### 5.3 월별기록 append (신규)
- `비품 주문 기록_YYYYMM.xlsx` 없으면 **템플릿(202605 구조: 입력·마스터·사용가이드) 복제 후 헤더/제목의 월 치환**해 생성.
- `입력` 시트 마지막 데이터 행 다음부터 append. 노란 셀 서식·드롭다운·합계 수식 **보존**(openpyxl은 기존 셀 스타일 유지; 합계가 범위참조면 행 추가로 자동 확장되는지 구현 시 검증).
- 단가 = round(금액/수량) (수량>0). 발주처·재구매주기·비고는 공란(사람이 후입력 가능).

### 5.4 월간 분석 병합 (신규)
loop 지침 절차 그대로:
1. 폴더에서 최신 `비품 주문 기록_YYYYMM.xlsx`·최신 `비품주문분석-vN.N.xlsx` 탐색.
2. 통합원본 `월` 컬럼과 비교해 **미반영 월** 판정.
3. 미반영 월 있음 → 담당자에게 "○월 반영할까요?" 확인. 없음(주문기록 미도착) → 가벼운 리마인드.
4. 승인 시: (a) 통합원본에 전월 행 append, (b) 월별 피벗 시트에 해당 월 컬럼 추가 + SUMIFS 재연결, (c) **신규 부서**를 부서별·부서x용도·부서x카테고리 시트에 행 추가, (d) 큰지출 TOP20 전기간 재산정, (e) 요약 대시보드 제목·월평균 분모·월별 추이 갱신. 네이비 헤더 서식 유지, 이전 버전 파일 **보존**, v(N+1).
5. **LibreOffice**(`soffice --headless --convert-to xlsx`)로 재계산 → 5개 집계 시트 합계 = 전체 총계, 신규 부서 누락 없음 검증.

### 5.5 기존 재고 자동화 중단 (선행)
- `supply.json`의 폴링/차감 비활성(예 `enabled:false` 또는 poll 루프 진입 차단). 슬랙 `재고`/`비품현황` 등 조회 명령은 남겨도 무방(읽기 전용). 붙여넣기 라우팅은 재고 가산 대신 **§4 파이프라인**으로 연결.
- 데이터 파일(입출고이력·재고현황)은 보존.

## 6. Drive 접근 — 로컬 파일 (커넥터 아님)

loop 지침은 Google Drive 커넥터(`search_files`, `download_file_content`)를 전제하나, 데몬 스케줄 작업은 **headless** 실행이라 claude.ai MCP 커넥터가 붙지 않을 수 있다. 폴더가 `G:\` 로컬 마운트이므로 **openpyxl 로컬 파일 직접 접근**으로 구현한다(탐색=디렉토리 glob, 읽기/쓰기=openpyxl). 커넥터 의존성 제거.

## 7. 백로그 복구 (6~8월)

- `#인총-기록저장소` 6/1~8월 히스토리에서 붙여넣기(구매표) 메시지 수집 → §5.1 파싱 → §5.2 분류 → 월별로 그룹핑해 `비품 주문 기록_2026{06,07,08}.xlsx` 생성/append → §5.4로 순차 반영(6월→7월→8월).
- 원본 붙여넣기에 금액·부서가 있으므로 복구 가능. 중복(같은 메시지 재수집) 방지 위해 통합원본 `블록ID`를 `YYYYMM#seq@줄` 형태로 부여하고 병합 시 dedup.
- 별도 **Phase 2**로 분리(§9): 우선 go-forward 파이프라인 검증 후 실행.

## 8. 엣지 케이스 / 에러 처리

- 엑셀이 열려 있음(`~$` 임시파일) → 그 파일 쓰기 스킵 + 슬랙 고지(재시도).
- 부서 미매칭(신규 부서) → 차단 없이 기록하되 슬랙 고지, 월간분석에서 파생 시트 행 추가.
- 붙여넣기 파싱 0건 → LLM 폴백(`_llm`), 그래도 0건이면 "표 인식 실패, 형식 확인" 안내.
- 금액 결측/0 → 기록은 하되 단가 공란 + 경고 표시.
- LibreOffice 검증 불일치 → 병합 파일 확정 보류, 이전 버전 유지, 슬랙 경고.

## 9. 구현 단계 (writing-plans 입력)

- **Phase 0** — 재고 자동화 중단(폴링/차감 OFF), 붙여넣기 라우팅을 신규 파이프라인으로 전환.
- **Phase 1 (go-forward)** — 파서 금액 확장 → 분류 엔진+캐시 → 월별기록 append → 슬랙 확인 메시지. (dry-run 우선)
- **Phase 2 (월간 분석)** — merge_month_into_analysis + LibreOffice 검증 + 스케줄/확인 게이트.
- **Phase 3 (백로그)** — 6~8월 슬랙 히스토리 복구 → 월별기록 → 분석 반영.

## 10. 검증

- 단위: 파서 금액 추출, 분류 캐시 결정성, 단가 계산, append 행 위치.
- 통합: 실제 5월 월별기록으로 병합 → v1.2 대비 합계 불변 확인(회귀). 샘플 붙여넣기 → 월별기록 append 후 openpyxl로 값 재확인.
- 정합: 병합 후 LibreOffice 재계산으로 5개 집계 시트 합계 = 통합원본 총계.
