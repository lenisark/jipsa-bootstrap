# 모듈 8 — 작업 객체 (Task Layer · jipsa 2.0)

> 전제: 모듈 1·5 완료. 데몬이 돌고 있어야 함.
> 휘발성 대화를 **상태 가진 작업(task)** 으로 승격한다. 데몬이 재시작해도 진행 중이던 일이 사라지지 않는다.

## 왜 필요한가

1.x는 모든 일이 대화로만 흐른다 — 데몬이 죽으면 진행 상황이 증발한다. 2.0은 작업을 SQLite 한 파일(`jipsa.db`)에 적재해 **대기 / 진행 / 막힘 / 완료 / 취소** 상태로 추적한다. 이 작업 객체는 모듈 9(승인 게이트)의 토대이기도 하다.

## 저장소

- 파일: `~/.claude/scripts/slack-jipsa/jipsa.db` (stdlib `sqlite3`, 외부 의존성 0)
- 기존 상태 파일들(`reminders.json`·`polls.json` 등)과 같은 폴더에 co-locate.
- WAL 모드 — 데몬·훅·sweeper가 동시에 써도 안전.
- 백업은 이 파일 하나만 복사하면 된다.

## 켜는 법

`channels.json`의 해당 채널에 `tasks_enabled: true` 한 줄을 추가한다.

```json
"C_PERSONAL_CHANNEL_ID": {
  "...": "...",
  "tasks_enabled": true
}
```

- 없거나 `false`면 1.x 동작 그대로 — 작업 명령이 일반 대화로 흐른다.
- 데몬 재시작 후 적용.

## 슬랙 명령

- `작업목록` — 해당 채널의 열린 작업(대기·진행·막힘)을 카드로 보여준다.
- `작업 <id 앞 6자리+> <상태>` — 상태 변경. 예: `작업 a1b2c3 완료`
  - 허용 전이만 동작한다(상태 기계). 예: 대기→완료는 막힘 — 대기→진행→완료 순서.

## 상태 기계

```
대기 ──착수──▶ 진행 ──완료──▶ 완료
 │              │ 막힘/승인대기
 │ 취소         ▼
 └────────────▶ 막힘 ──해소(다시 진행)──┘
```

- 완료·취소는 종결 상태 — 더 이상 바뀌지 않는다.

## 점진 적용 원칙 (최소 diff)

1.x의 알리미·FAQ·투표·요약은 **그대로 둔다**. 작업 객체는 신규 기능부터 얹는 것이라, 기존 기능을 작업 위로 옮길 필요는 없다(원하면 나중에). 신규 채널 하나에서 `tasks_enabled`만 켜보고 익숙해진 뒤 확장하면 된다.

## 셋업 순서 (AI가 진행)

1. `channels.json`의 대상 채널에 `tasks_enabled: true` 추가.
2. 데몬 재시작.
3. 검증 — 채널에서 `작업목록` → "열린 작업이 없어요" 응답 확인(DB 초기화됨).
4. `도움말` → 하단에 *📋 작업* 섹션이 보이는지 확인.
