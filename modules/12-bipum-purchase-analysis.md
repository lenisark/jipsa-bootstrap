# 모듈 12 — 비품 구매기록·월간분석 (jipsa 2.0 P2)

> 전제: 모듈 11(비품관리) 코드 자산을 재사용. `purchase.json`이 있으면 데몬이 **구매기록 모드**로 전환되어 재고 폴링/차감(모듈 11) 대신 이 모듈이 활성화된다.
> 슬랙에 붙여넣은 구매표를 **데몬 전용 누적 구매로그**(`비품 구매기록_자동.xlsx`)로 적재하고, 매달 자동으로 "이번 달 반영 제안"을 올려 담당자가 확정하면 누적 분석 파일에 병합한다.

> **왜 별도 로그인가:** 사람이 손으로 채우던 `비품 주문 기록_YYYYMM.xlsx` `입력` 시트는 단순 리스트가 아니라 데이터 창(r5~54)·합계행·요약 SUMIFS가 박힌 **정형 양식**이라, 프로그램이 append하면 합계/요약 범위 밖으로 나가고 읽을 때 합계·요약행을 데이터로 오독한다. 그래서 데몬은 그 양식을 건드리지 않고 **수식·합계 없는 단순 플랫 로그**(시트 `기록`, 헤더 1행 + 데이터)에만 적재한다. **손입력 양식(`비품 주문 기록_YYYYMM.xlsx`)은 이제 사용하지 않으며, 분석의 원천은 이 자동 로그다.**

## 무엇을 하나

부서 채널에 구매표(엑셀/그룹웨어 복사)를 붙여넣으면 집사가 품명·수량·금액을 파싱하고, 품목별 *용도*·*카테고리*를 LLM으로 분류(결과는 캐시에 저장돼 재분류 없이 결정적으로 재사용)한 뒤, 누적 구매로그 `비품 구매기록_자동.xlsx`(시트 `기록`)에 `월|일자|부서|용도|카테고리|품목|수량|단가|금액|블록ID` 한 행을 추가한다(블록ID는 그 달 내 순번). 매달 지정한 영업일이 되면 로그에서 지난달분을 골라 **월간 누적 분석 파일**(`{yymmdd}-{dept_code}-비품주문분석-v{maj}.{min}.xlsx`)에 반영할지 제안(dry_run)하고, 담당자가 `분석 갱신 확정`으로 승인해야만 실제로 새 버전 파일이 저장된다.

## 흐름

```
[슬랙 채널: 구매표 붙여넣기 (입고등록 또는 표 단독 붙여넣기)]
        │
   [표 파싱: 품명·수량·금액·부서 (+금액 포함, 팩 개수 곱셈, 규격 보존)]
        │
   [용도·카테고리 분류: classify_with_cache — 캐시 적중 시 LLM 미사용]
        │
   [부서명 정규화: known_depts/dept_aliases — 매칭 실패 시 "신규 부서 후보" 경고만]
        │
   [비품 구매기록_자동.xlsx [기록] 시트에 append (누적, 월 컬럼으로 구분)]
        │
        ▼ (매달 schedule.day 영업일 schedule.hour 이후, 자동 1회)
   [merge_month_into_analysis(dry_run=True): 로그에서 해당 월만 필터 → 채널에 "N월 분석 갱신 제안" 게시]
        │
   담당자가 `분석 갱신 확정 [YYYYMM]` 입력
        │
   [최신 분석 파일 로드 → 통합원본에 신규 행 append → 파생 피벗시트 SUMIFS 확장]
        │
   [새 버전 파일 저장: {yymmdd}-{dept_code}-비품주문분석-v{maj}.{min+1}.xlsx (원본 불변)]
```

**핵심 불변식:**
- 분류(LLM)는 *품목명→{용도,카테고리}* 매칭에만 쓰이고 캐시(`classify_cache` 파일)에 저장되어 같은 품목명은 이후 결정적으로 재사용된다.
- 월간 분석 병합(`compute_pivots`/`_apply_pivots`)은 100% 결정적 코드(LLM 미사용)이며, 자동 스케줄은 **제안(dry_run)만** 하고 파일을 쓰지 않는다. 실제 반영은 담당자의 명시적 확정이 있어야만 일어난다.
- 파생 피벗 시트는 통합원본을 참조하는 SUMIFS 수식이라, 병합 시 신규 월 컬럼·신규 부서 행만 추가하고 기존 셀 값(수식)은 절대 덮어쓰지 않는다.

## 설정 (purchase.json)

`templates/scripts/slack-jipsa/purchase.json.example`을 복사해 `~/.claude/scripts/slack-jipsa/purchase.json`으로 배치한 뒤 실측값으로 채운다.

```bash
cp templates/scripts/slack-jipsa/purchase.json.example ~/.claude/scripts/slack-jipsa/purchase.json
```

| 필드 | 설명 | 주의 |
|------|------|------|
| `mode` | `"purchase"`로 고정 | 이 값이 있어야 데몬이 구매기록 모드로 전환(재고 폴링/차감 비활성) |
| `channel` | 구매표를 받고 월간 제안을 게시할 슬랙 채널 ID | 부서 채널 권장 |
| `folder` | 월별기록·분석 엑셀이 있는 로컬 경로 | G드라이브 마운트 경로(`G:/공유 드라이브/…`) |
| `dept_code` | 분석 파일명에 들어가는 부서 코드 | 예: `HGA` |
| `purchase_log` | 데몬 전용 누적 구매로그 파일명 | 예: `비품 구매기록_자동.xlsx`. 없으면 최초 적재 시 자동 생성(시트 `기록`) |
| `analysis_prefix` | 분석 파일명 접두어 | `latest_analysis`가 `*{prefix}-v*.xlsx` 패턴으로 최신 버전을 찾음 |
| `classify_cache` | 품목→{용도,카테고리} 분류 캐시 JSON 경로 | 파일이 없으면 최초 실행 시 자동 생성 |
| `known_depts` | 부서명 정규화 어휘(고정 마스터) | 여기 없으면 "신규 부서 후보" 경고가 붙는다 |
| `dept_aliases` | 원문 부서명→표준 부서명 수동 매핑 | 기본 `{}`. 오탐이 반복되면 여기 추가 |
| `managers` | 비품 담당자 슬랙 User ID 목록 | `분석 갱신[ 확정]`·`입고등록`·`출고`/`실사` 명령 권한자(구매기록 모드에서는 `supply.json`의 `managers`와 합집합으로 적용됨) |

| `schedule.hour` | 제안을 올릴 시각(시) | 이 시각 이후 첫 폴링 주기(30분 간격 점검)에 발송 |
| `dry_run` | (현재 구매기록 모드 자체 로직은 사용 안 함, 레거시 supply 필드 흔적) | 구매기록 모드에서 실질적 안전장치는 "제안 후 수동 확정"이며 이 필드는 참고용 |

## 슬랙 명령

- **`입고등록`** (붙여넣기) — 구매표를 파싱해 구매기록에 적재. 표를 같은 메시지에 붙이면 즉시 처리, 명령만 먼저 보내면 3분간 다음 메시지를 표로 대기(`_inbound_wait`). 담당자만(구매기록 모드에서는 `supply.json` + `purchase.json` 양쪽 `managers`가 모두 권한자 — `handle_supply_command`가 `mode: "purchase"`일 때 두 목록을 합집합으로 검사한다). `출고`/`실사`도 동일하게 적용된다.
- **`분석 갱신 [YYYYMM]`** — 해당 월(생략 시 지난달) 반영 제안을 dry_run으로 계산해 채널에 게시(신규 건수·해당 월 합계·전체 총계). `purchase.json`의 `managers`만 권한자(이 명령은 별도로 게이팅됨, `supply.json` managers는 관여하지 않음).
- **`분석 갱신 확정 [YYYYMM]`** — 실제로 병합해 새 버전 분석 파일을 저장. 담당자만.
- **월간 자동 제안** — `schedule.enabled`면 매달 `schedule.day` 영업일 `schedule.hour` 이후 지난달분을 자동으로 dry_run 제안 게시(월 1회, `purchase_state.json`의 `last_fired`로 중복 방지). 자동 확정은 없다 — 항상 사람이 `분석 갱신 확정`을 입력해야 파일이 바뀐다.

## 셋업 순서 (AI가 진행)

1. **재고 폴링 중단** — `purchase.json`을 배치하고 `mode: "purchase"`로 두면 데몬이 기동 시 자동으로 재고 폴링(모듈 11)을 비활성화하고 이 모듈의 월간 스케줄러만 띄운다(`main()`의 `_pcfg.get('mode') == 'purchase'` 분기).
2. **`purchase.json` 배치** — 위 표의 값(특히 `folder`, `dept_code`, `known_depts`, `managers`)을 실측값으로 채운다.
3. **`supply.json` 유지 필요(★배포 노트 참고)** — 구매 전용 배포라도 `supply.json`을 삭제하지 말 것.
4. `purchase.py`·`purchase_store.py` 배치:
   ```bash
   cp templates/scripts/slack-jipsa/purchase.py ~/.claude/scripts/slack-jipsa/
   cp templates/scripts/slack-jipsa/purchase_store.py ~/.claude/scripts/slack-jipsa/
   ```
5. 데몬 재시작.
6. **dry_run 관찰** — `입고등록`으로 실제 구매표 1~2건을 넣어 파싱·분류·부서 정규화가 예상과 맞는지 확인. 월말에는 `분석 갱신`(확정 없이)으로 제안 내용만 먼저 확인.
7. **실가동** — 제안 내용이 맞으면 `분석 갱신 확정`으로 반영. 이후엔 월간 자동 제안 → 담당자 확정의 반복.

## ★ 중요 배포 노트

- **`입고등록`·`분석 갱신[ 확정]` 명령은 모두 `handle_supply_command`를 경유한다.** 이 함수는 진입 즉시 `supply.json`(`SUPPLY_CONFIG_FILE`)을 읽어 없으면(`None`) 바로 `False`를 반환하고 아무 명령도 처리하지 않는다. 즉 **구매 전용으로만 쓰더라도 `supply.json`이 존재해야** `입고등록`/`분석 갱신` 명령이 동작한다. `purchase.json`만 있고 `supply.json`이 없으면 두 명령 모두 조용히 무시된다(에러 메시지도 없음). 재고 관리를 아예 안 쓰더라도 `supply.json`은 최소 형태로 유지할 것.
- **월간 자동 스케줄은 dry_run 제안만 한다.** `_purchase_monthly_loop`는 `merge_month_into_analysis(..., dry_run=True)`만 호출하며 파일을 쓰지 않는다. 실제 파일 반영(새 버전 저장)은 담당자가 `분석 갱신 확정`을 명시적으로 입력했을 때(`confirm=True` → `dry_run=False`)만 일어난다.
- **`큰지출_TOP20`과 요약 대시보드 추이행은 자동 갱신되지 않는다(현재 한계).** `_apply_pivots`는 `PIVOT_LAYOUT`에 정의된 5개 시트(부서별_월별·카테고리별_월별·용도별_월별·부서x용도·부서x카테고리)만 SUMIFS 기반으로 확장한다. `큰지출_TOP20`(정적 스냅샷)과 `요약_대시보드`(수동 라벨 집계)는 병합 시 코드가 손대지 않으므로, 병합 후 이 두 곳은 **엑셀에서 열어 수동으로 확인/갱신**해야 한다.
- 파생 피벗 시트(부서별_월별 등)는 새 월 컬럼/신규 부서 행만 추가되고 기존 값(수식)은 보존되므로, 엑셀에서 파일을 열면 자동 재계산되어 기존 월(예: 5월까지) 합계는 구조적으로 불변이다.
- **분석 워크북은 차트/이미지가 없는 셀·수식 기반 설계이며(검증됨), 그래서 병합이 무손실이다.** `write_merged_analysis`는 `openpyxl.load_workbook` → 수정 → 저장 방식으로 병합하는데, openpyxl은 네이티브 엑셀 차트·삽입 이미지를 로드/저장 왕복 시 보존하지 않고 드롭한다. 실제 운영 파일(`260608-HGA-비품주문분석-v1.2.xlsx`)을 확인한 결과 차트 0개·이미지 0개로, 대시보드가 전부 셀 값/수식(SUMIFS 등)으로만 구성돼 있어 현재 설계에서는 이 유실 경로가 실현되지 않는다. **주의**: 앞으로 이 워크북에 네이티브 차트나 이미지를 추가하면 `분석 갱신 확정` 때 소리 없이 사라진다 — 대시보드는 계속 수식/셀 기반으로 유지할 것(권장). 부득이 차트를 넣어야 한다면 그 전에 `write_merged_analysis`(및 `openpyxl` 저장 경로 전반)를 차트/이미지 보존 방식으로 재검토해야 한다. `tests/test_purchase_regression.py::Regression::test_no_charts_or_images_in_analysis_file`가 실 파일 기준으로 이 상태를 회귀 감시한다(차트/이미지가 생기면 테스트가 실패해 알려준다).

## 알려진 후속 과제 (미구현, 문서화만)

- `classify_items`/`classify_with_cache`는 `guide_text` 파라미터를 받아 프롬프트에 분류 가이드를 주입할 수 있는 구조로 이미 열려 있지만, 현재는 `cfg.get('guide_text', '')`가 항상 빈 문자열이라 **분류_가이드 시트 내용을 실제로 읽어 주입하는 로직은 아직 없다**(built-in 카테고리/용도 어휘 + 기본 프롬프트만 사용). 분류 정확도를 더 올리려면 이후 별도 태스크로 분석 파일의 `분류_가이드` 시트를 읽어 `guide_text`에 넣는 기능을 추가해야 한다.

## 검증(선택) — LibreOffice 교차검증

이 환경에는 `soffice`(LibreOffice)가 설치돼 있지 않아 자동 재계산 검증은 수행하지 않았다. `soffice`가 설치된 환경이라면 아래로 병합 결과 파일을 강제 재계산해 교차검증할 수 있다:

```bash
soffice --headless --convert-to xlsx --outdir /tmp/recalc "{병합된 분석 파일}.xlsx"
```

재계산된 파일을 열어 5개 집계 시트(부서별_월별·카테고리별_월별·용도별_월별·부서x용도·부서x카테고리)의 각 합계 셀이 `통합원본` 전체 금액 합(`compute_pivots`의 `총계`)과 일치하는지 확인한다. `soffice`가 없는 환경에서는 수식 문자열이 기존 SUMIFS 패턴을 그대로 복제해 생성되므로(좌표·필터열은 `PIVOT_LAYOUT`에 상수화) 구조적으로 정확성이 보장된다 — 값 자체는 엑셀에서 열 때 재계산된다.
